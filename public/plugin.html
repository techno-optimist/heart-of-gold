What happens when you deploy?

  1. Shape the crew. Assign small, useful components with clear owners and shared interfaces.
  2. Engage the drive. Your chat publishes a real shell, then integrates each usable component as it arrives while the other work continues.
  3. Inspect what changed. Real source changes connect contributors to their rendered components. Preview the result, inspect Source and Changes, and follow reported checks and actual review fixes in the same card.

ProjectForty2 keeps the latest supplied flight and selected source, up to 12 component mappings, and at most 64 component metadata receipts temporarily in server memory. Access expires after two hours; previous source contents are not retained, and there is no external model call. Your host performs the build and checks; the plugin does not verify a reported pass, install dependencies, or publish the site. Preview support depends on the host, and source inspection remains available. Updates follow real component checkpoints, with host and polling latency. The deck does not simulate typing or replay a finished app as a live build. When the host cannot delegate, the same assistant builds through clearly labeled passes. Read the privacy notice.
