What happens when you deploy?

  1. Shape the crew. Give each role an assignment and something concrete to bring back.
  2. Engage the drive. Your chat uses its available tools to create the actual files, with workers when supported.
  3. Inspect what changed. Selected source files, crew attribution, and reported checks update the same card at real milestones. Preview supported code, inspect a contribution, or challenge a branch.

ProjectForty2 keeps the latest supplied flight and selected project files temporarily in server memory. Access expires after two hours; there is no durable source history or external model call. Your host performs the build and checks; the plugin does not verify a reported pass, install dependencies, or publish the site. Preview support depends on the host, and source inspection remains available. Updates follow real artifact revisions and reported milestones, not live model tokens. Read the privacy notice.
