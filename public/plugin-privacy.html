The Heart of Gold plugin helps you shape a crew and inspect its work inside ChatGPT or another compatible host. The plugin and the standalone website use different execution paths.

What reaches ProjectForty2

When the host calls a Heart of Gold tool, it sends the supplied mission, crew assignments, constraints, contributions, evidence links, and summaries to the ProjectForty2 MCP service. The service validates that information, keeps the latest flight snapshot temporarily in server memory, and returns data to one flight deck as it updates. It does not independently observe your agents or request your full chat history.

Processing and storage

The plugin service keeps the latest snapshot for each flight in temporary process memory. Access expires two hours after the flight is created; reads and updates do not extend that deadline. Expired entries are removed on access or the next cleanup sweep, scheduled every 60 seconds. Only the latest snapshot is kept; previous versions are not retained. Restarting or shutting down the service clears its flight state. It has no durable mission database or saved cross-session flight history. Each flight is limited to 96 KiB, with at most 128 flights and 8 MiB across the process. Capacity limits reject new or oversized work rather than evicting an active flight. It does not intentionally write request bodies or contribution text to application logs. Hosting and network providers can process request metadata, such as addresses, timestamps, routes, and errors, under their own practices. This is not a promise that content never leaves your chat.

Private flight access

The host receives a private write capability for the current flight, and its widget receives a separate read capability. These are random access tokens, not provider credentials or account sign-in. Anyone who obtains a valid capability can exercise its access until the flight expires. They are sent in tool arguments, never in a public flight URL. Keep them out of public messages, evidence links, and delegated-worker prompts. The service has no flight-listing endpoint or plugin account cookie.

Model usage and credentials

The plugin does not request an OpenAI API key, a ChatGPT password, or an OAuth token. Reasoning and any native delegation happen through the capabilities available in your host account. Host plan limits and policies apply. The plugin service itself makes no model-provider calls. The standalone website’s optional API-key connection is separate and is not required by the plugin.

Your controls

You choose what to include in the mission and reported snapshots. Keep credentials out of task text. Your host controls chat retention, plugin installation, tool permissions, and removal. Removing the plugin stops future use through that installation; it does not immediately erase the temporary server snapshot. Flight access expires on its fixed deadline, and service restart clears state. Your host can retain conversation text, tool arguments, and displayed results under its own policies; manage those through its controls.

Questions and project information

Review the open-source project and its plugin documentation. Public project issues are suitable for general questions and reproducible bugs; do not post private task content or credentials there.
